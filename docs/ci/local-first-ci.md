# Local-first CI/CD

Operationally complete, local-first CI/CD for Nabatable: pull requests and `main` are tested by a Mac controller in disposable VMs, a hosted release gate that runs only from protected `main` turns evidence into merge and deploy decisions, an operational-control Worker keeps the pieces honest, and delivery to staging and production is scripted, evidenced and reversible. This page is the entry point; every part links to its own runbook.

Companion documents: `docs/ci/release-gate.md` (gate semantics, required checks), `docs/ci/governance.md` (GitHub Apps, environments, transfer checklist), `docs/runbooks/local-ci.md` (the Mac), `docs/runbooks/staging-release.md` (delivery), `docs/runbooks/monitoring.md`, `docs/runbooks/recovery.md`, `docs/DATABASE_MIGRATIONS.md` (promotion safety), `cloudflare/operational-control/README.md`.

### The request tuple

Every unit of work is identified by `{ repositoryId, profile, prNumber?, headSha, baseSha, testedSha, policyVersion, imageDigest, controllerVersion, attempt }` (`scripts/ci/contracts/request.ts`). `testedSha` is the synthetic merge SHA for PRs and the merged SHA for `main`; `policyVersion` is `YYYY-MM-DD.N` (`2026-09-04.1` today) and must agree between `config/ci/policy.json`, `scripts/ci/profiles/catalog.ts` and the controller; `imageDigest` must be an approved executor job image. The deterministic dedup key (`ci:v1:<sha256>`) and the check-run `external_id` (`nabatable-ci/v1:<fields>`) are derived from the tuple; the gate refuses anything that does not bind exactly.

### Trust and routing

`config/ci/trust-policy.json` classifies from repository metadata only. Head repository id different from the trusted id (forks) is rejected before any fetch; automation identities and unknown actors are routed to hosted CI; labels, branches and titles are ignored. While `trustedRepositoryId` and `actorPolicy.localActors` are unconfigured every PR is routed hosted and only `main`/`nightly` run locally. Priority on the Mac is `main` > PR (FIFO) > nightly, with a two-main-then-PR fairness rule, supersession of older PR revisions, and nightly preemption only at suite boundaries.

### Runtime policy

`activeRuntime: node22` (hosted workflows and the job image), `candidateRuntime: node24` (production Vercel). Every profile, manifest and heartbeat records both. Node 24 becomes active only after a full nightly profile and a staging release pass on a node24 image digest listed in `config/ci/policy.json`, with package `engines` and every workflow `node-version` bumped in the same reviewed change. pnpm is pinned to `10.34.5`.

## Qualification checklist

Run before the local check becomes required (end of Phase 3) and after any change under `infra/local-ci/`, `scripts/ci/executor/` or `scripts/ci/controller/`. The detailed procedures are in `docs/runbooks/local-ci.md` (Phase 2 and Phase 3 lists).

- [ ] Isolation: no host mounts, no port forwards, no proxy env in the VM; job container non-root, `cap-drop=ALL`, seccomp denies (`unshare`, `mount`, `ptrace`, `keyctl`) verified inside a job.
- [ ] Egress: phase `prep` reaches only allowlisted hosts through the guest proxy; phase `test` reaches nothing; `egress.sh status` reports the live phase and the executor aborts on `unknown`; the pinned Docker Engine lets the `--internal` job network reach its gateway (or the documented fallback is adopted).
- [ ] Pinning: golden image digest, Docker Engine version, job image RepoDigest, Playwright and pnpm versions, `testedSha`; a mismatch anywhere is refused before any instance starts (`pnpm ci:executor --dry-run` shows `REQUEST REJECTED` / `UNCONFIGURED`).
- [ ] Disposability: no `nabatable-ci-<jobId>` instance survives a request; the `nabatable-ci` Docker context is unbound after each job; the default and `desktop-linux` contexts are never touched.
- [ ] Evidence: a failing test lands its bundle in R2 and the check run is `failure`; an upload failure is `error`; no evidence file contains a token, guest PII or an unredacted URL credential; the gate parses every published document.
- [ ] Controller: reconcile-on-start recovers interrupted attempts without a false `success`; supersession cancels the older PR revision; nightly preemption re-queues at a suite boundary; the sleep assertion (`caffeinate -i -s -w <pid>`) is held for the daemon lifetime; battery, thermal, memory and disk admission defers and resumes.
- [ ] Operations: cold reboot with FileVault, lid closed with AC + display, lid closed without display (must fail the deadline, never lie), battery, VPN flap, five-minute network loss (heartbeat stale, `ops:verify` alerts, hosted fallback runs), dedicated-window edge, release update and rollback via the `current` symlink.
- [ ] Hosted side: `pnpm ci:contracts:validate` zero violations and zero placeholder warnings; `Release gate` refuses a tampered `external_id`, a wrong App id, a superseded head and a skipped required suite (run the refusal matrix from `tests/scripts/ci/gate/evaluate.test.ts` against staging fixtures); `Hosted profile fallback` accepted only with the approved `CI fallback` deployment record.
- [ ] Runtime candidate: the same list passes with the node24 job image before `candidateRuntime` may be promoted.

## External provisioning checklist

Everything below is done by a human administrator outside the repository. Every item is a `REPLACE_ME_*` (or `replace-me-*` for R2 bucket names) placeholder today, and every script validates the placeholder as unconfigured and refuses; nothing is silently used.

## Assumptions and constraints

- **No production or staging credentials locally.** The CI Mac holds only the local-ci App key, the write-only evidence token and the heartbeat token, in the `nabatable-ci` login Keychain. Jobs see a sanitized `test-*` environment. Nothing on the Mac can reach Supabase, Vercel, Twilio or Resend for real environments.
- **Forks never run locally.** Trust is decided from repository ids before any fetch; fork PRs get `Fork profile` (no secrets, no caches) whose evidence the gate always rejects. A maintainer dispatches a real request to merge.
- **`Release gate` is the authority.** Merge and deploy decisions come only from the gate running from protected `main`. Policy lives in `config/ci/policy.json` and is locked to `scripts/ci/profiles` by `pnpm ci:contracts:validate`; refusals are never overridden by editing policy, disabling checks or bypassing protection.
- **Fail closed everywhere.** Missing, stale or unknown evidence, unconfigured bindings (`REPLACE_ME_*` / `replace-me-*`), a wrong repository id, App id, installation id, workflow id or SHA tuple all reject. A refused run publishes `failure` or `error`, never silence and never `success`.
- **Runtime.** Hosted workflows are Node 22 (`activeRuntime`); production Vercel is Node 24 (`candidateRuntime`). `engines` and workflow `node-version` are not flipped until qualification (Phase 6). pnpm is `10.34.5`.
- **Per-job disposable VMs.** The executor cold-clones a digest-verified golden Lima image per job and destroys it in every path. The infra runbook and the executor agree on this model; the golden image is produced by `infra/local-ci/bin/build-base-image.sh` and must be rebuilt when Playwright, pnpm or the Docker Engine pin changes.
- **One controller, one Mac.** The controller runs as a per-user LaunchAgent (not a LaunchDaemon) because it needs the service account's unlocked login Keychain and Virtualization.framework from a user session; the account must be FileVault-enabled and unlock the disk after a cold boot. Capacity is the Mac's; the hosted fallback exists for outages, not for scale.
- **Evidence retention.** CI evidence in R2 expires after 14 days; release and drill artifacts are retained for at least 90 days (400 for production and drills); all evidence is redacted (manifests, digests, decisions) and never contains dumps, tokens or guest data.
- **Enterprise dependency.** Environment protection on a private repository requires GitHub Enterprise. Until then fallback evidence is untrusted and `Protected delivery` runs by dispatch with administrator-enforced approval.
- **Staging delivers nothing.** `DELIVERY_MODE=sink`, `RESEND_USE_MOCK=true` and staging-only destination hosts keep staging from reaching guests; the WhatsApp to SMS fallback is therefore not observable in staging and stays a `test.fixme` proof.
- **First cycles are intentionally invalid.** A fresh operational-control evidence bucket makes the first five-minute cycle `evidence_missing`; `ops:verify` heartbeats only after a fully valid cycle; the uptime monitor grace period must be at least 75 minutes.
- **Unverified until infrastructure exists.** Everything that touches Lima, Docker, nftables, R2, the GitHub API, Vercel, wrangler, Supabase or PostgreSQL client tools is implemented against injectable interfaces and tested with fakes and real `git` only; the first real runs must confirm CLI output formats (`wrangler versions upload`, `supabase migration list`, `vercel --target=staging`) and adjust the parsers if wording differs.
