# Implementation Plan: Manager Daily Summary Domain Tail

## Objective

We will append `app.nabatable.com` to the manager daily summary SMS so managers always see the Nabatable app URL in the canonical summary message.

## Success Criteria

- [ ] Every manager daily summary SMS generated by the shared formatter ends with `app.nabatable.com`.
- [ ] Existing formatter and worker tests pass with the new canonical copy.

## Architecture & Components

- `lib/ops/daily-booking-summary.ts`: canonical message formatter update.
- `tests/utils/dashboardSummary.test.ts`: direct formatter proof.
- `tests/cloudflare/sms-summary-gateway.test.ts`: downstream worker proof.

## Data Flow & API Contracts

- No API contract changes.
- SMS summary payload structure is unchanged apart from the appended terminal text in the generated `message` string.

## UI/UX States

- Not applicable; no UI surface changes.

## Edge Cases

- Preserve the optional `Other ...` sentence when non-lunch/dinner bookings exist, then append the app domain after all summary sentences.
- Preserve empty and zero-booking output formatting.

## Testing Strategy

- Focused Vitest coverage for `tests/utils/dashboardSummary.test.ts`.
- Focused Vitest coverage for `tests/cloudflare/sms-summary-gateway.test.ts`.

- No feature flag.
