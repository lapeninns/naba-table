# Implementation Plan: Copy Cornerhouse Data to New Restaurant Seed

## Objective

We will clone scoped Corner House config data into a new restaurant named "The Railway Pub" in production.

## Success Criteria

- [ ] New restaurant created with requested name/slug.
- [ ] Selected config tables copied for the new restaurant without cross-tenant leakage.
- [ ] PII handling matches approved scope.

## Architecture & Components

- `scripts/seed-railway-from-cornerhouse.ts`: tenant-scoped copy script.

## Data Flow & API Contracts

- Uses Supabase service role client; reads Corner House rows and inserts new rows with new restaurant_id.
- Source slug: `the-corner-house-pub-cambridge`.
- Target name: `The Railway Pub` (slug auto-generated by server).

- Production guardrails required for apply mode.

- Apply mode only after approval.

- `allowed_capacities`

- `restaurant_service_periods`
- `zones`
- `table_inventory`
- `table_adjacencies`
- `restaurant_capacity_rules`
