# design-sync notes — Nabatable Platform DS

Target project: **Nabatable Platform DS** (`79fc9aba-dee5-4b3d-a324-7574091e5a20`). A SEPARATE
project from the hand-built "Nabatable Design System" (`f4267983-…`, Radix Luma + Mise) — do
NOT sync into that one; it's hand-authored and would be clobbered.

## Shape & curation

- **shape: package, synth-entry.** This is a Next.js _app_ (`private:true`, no library build/`dist`),
  not a packaged DS. The component surface is curated via a hand-authored barrel + `componentSrcMap`.
- **Barrel:** `.design-sync/entry.tsx` re-exports the full surface (212 names) onto the window global;
  `componentSrcMap` (89) is the carded **primary** set only. Generated by the scratch scripts
  `curate.mjs` + `gen.mjs` (scanned dirs: `components/{ui,layout,mobile}`, `src/components/{ui,shared,guest/ui,features/ops-shell}`,
  `reserve/shared/ui`). Primaries = file-name-matching / non-prefix exports; compound sub-parts
  (CardHeader, DialogContent, SidebarMenu…) live in the barrel but get no card.
- `reserve/shared/ui/*` are mostly `export * from '@/components/ui/*'` aliases → collapsed to the
  root shadcn primitives. Only `Field` + `Icon` are reserve-specific.
- Default-exported components (`export default function Footer`) are re-exported as
  `export { default as Footer }` — the barrel generator handles this; a plain named re-export
  silently drops them from the global (`[BUNDLE_EXPORT]`).

## Preview rendering (the hard-won bits)

- **process polyfill — load-bearing.** `.design-sync/shims/process-polyfill.ts` is imported FIRST in
  the barrel. Components transitively import app config/analytics (`@/config`, posthog, supabase)
  that read `process.env.*` at module-eval; without the polyfill every component throws
  `process is not defined`. `env` is seeded with **non-secret preview placeholders**
  (`NEXT_PUBLIC_SUPABASE_URL/ANON_KEY` are `assertEnv`'d in `lib/env-client.ts` → must be non-empty)
  and a Proxy returns `''` for unknown keys.
- **next/\* shims:** `next/link`→`<a>`, `next/image`→`<img>`, `next/navigation`→no-op router, via
  `.design-sync/shims/next-*` mapped in `.design-sync/tsconfig.dsync.json` (`cfg.tsconfig`).
- **tsconfig dir-fix:** the converter's tsconfig-paths plugin resolves an alias→**directory** before
  `/index` and hands esbuild a dir (`Cannot read file … is a directory`). `tsconfig.dsync.json` carries
  explicit non-wildcard entries for the 5 alias dir-imports (`@/config`, `@/lib/utils`,
  `@reserve/shared/{booking,occasions,time}`). Re-run `scratchpad/resolve-fix.mjs` if new ones appear.
- **CSS:** Tailwind v4. Recompile via the durable wrapper `.design-sync/css-entry.css` (it `@import`s
  `globals.css` + `@source`s the previews) → `.design-sync/compiled/ds.css` (`cfg.cssEntry`, gitignored):
  `.ds-sync/node_modules/.bin/tailwindcss -i .design-sync/css-entry.css -o .design-sync/compiled/ds.css`.
  Tokens (`--primary` = cobalt `227 84% 49%` / #1447E6, `--pg-*`) inline into `_ds_bundle.css`; no
  separate tokens package.
- **playwright:** render check needs `playwright@1.60.0` (pins chromium **1223**, which is what the
  `~/.cache/ms-playwright` cache has). Repo pins `@playwright/test@1.58.1` (chromium 1208) — do NOT
  use it for the render check; mismatched build = "Executable doesn't exist". Installed in `.ds-sync`.

## Preview-authoring gotchas (from the author waves)

- **Compiled CSS is scanned from APP source only.** `.design-sync/` is a dotdir → Tailwind v4
  auto-content-detection SKIPS it, so utilities used ONLY in `.design-sync/previews/*.tsx` (and any
  arbitrary-value class like `bg-[#hex]`, `w-[200px]`) are absent from `_ds_bundle.css` and render as
  no-ops. The fold recompiles `ds.css` with `@source "../previews/*.tsx"` so preview utilities are
  included. When authoring, prefer utilities the app already uses; `bg-slate-300` is in-bundle and
  reliable for visible placeholders (`bg-muted` is too faint; `bg-slate-200`/zinc/gray/neutral are not
  in-bundle). `preview-rebuild` does NOT recompile Tailwind — only a CSS recompile does.
- **Skeleton\* components OVERWRITE `className`, they don't `cn()`-merge it.** `skeletons.tsx` renders
  `<Skeleton className="h-7 w-48" {...props}/>` — the spread wins (last write), so a passed `className`
  REPLACES the built-in height → bars render at height 0 (invisible). Always re-include the height
  (`h-4`/`h-7`/…) when overriding a Skeleton's className.

## Custom-surface preview notes (Guest / Ops)

- Tokens (`--primary` cobalt, `--pg-*`, `--foreground`) are on `:root` AND the theme selectors, so
  guest+ops components render styled with NO theme wrapper. (Confirmed by all 3 author waves.)
- **PageSection / FeatureCard are DARK hero surfaces**: their white text + `pg-*-dark` panel rules are
  descendant-scoped to `[data-theme='guest'|'app']`/`.guest-theme`. Preview must wrap in `.guest-theme`
  AND set an explicit dark background (e.g. `#0b1020`) or the white text is invisible on the white sheet.
- **FeatureCard `icon` is a `ReactNode`** — pass `icon={<Calendar className="size-6"/>}`, not a component.
- **OpsStatusBadge tones** map success/warning/info/neutral → cobalt-tint, only `danger`=red, `muted`=grey
  (`lib/ops/status-tones.ts`); a tone sweep is mostly cobalt by design, not a bug.
- `guest-outline`/`guest-ghost` (CVA variants over near-white `--pg-bg`/`--pg-border`) read as bare text on
  a white sheet — place them on a `bg-muted/40` backdrop in the preview.

## Known warns (triaged — not new)

- `[TOKENS_MISSING]` `--radius-full, --pg-shadow-floating, --pg-shadow-soft, --tw` — referenced but
  not in any shipped stylesheet; runtime/Tailwind-internal, non-blocking.

## Overlays

- Dialog / Select / DropdownMenu / Tooltip use `cfg.overrides.<Name> = {cardMode:"single", viewport}`
  and render open via Radix `defaultOpen`. Changing `cfg.overrides` forces a full `package-build`
  (`[CONFIG_STALE]` on `preview-rebuild` otherwise).

## Re-sync risks

- `process.env` seed values are **inlined placeholders** in the polyfill — they won't reflect real
  config and could drift if `lib/env-client.ts` adds new required (`assertEnv`) vars.
- `.design-sync/compiled/ds.css` is a generated artifact (gitignored) — MUST be regenerated before any
  re-sync build, else `cfg.cssEntry` points at stale/absent CSS.
- The curation scan (`curate.mjs`/`gen.mjs`) lives in the scratchpad, not the repo — `componentSrcMap`
  - `entry.tsx` are the committed truth. New components must be added to both by hand or by re-running
    the scan.
