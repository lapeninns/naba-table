# Durable Object state classification

Durable Objects hold Worker-local state that is not part of the Supabase backup. Each class is classified so an operator knows what a fresh namespace (new Worker name, class rename, or account migration) costs and how to recover.

| Worker              | Class                      | Classification                         | Recovery                                                                                                                                                                                                                                                                                                                                                                                                           |
| ------------------- | -------------------------- | -------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| email-queue-gateway | `EmailQueueState`          | Rebuildable (derived)                  | Per-restaurant queue coordination for the Next.js email processor. Source of truth is the `email_delivery_attempts` ledger in Postgres; a fresh object starts idle and the app re-enqueues on its next scheduled pass. No replay needed.                                                                                                                                                                           |
| email-queue-gateway | `RateLimitState`           | Rebuildable (ephemeral)                | Sliding-window counters. Loss only relaxes limits for one window; nothing to restore.                                                                                                                                                                                                                                                                                                                              |
| email-queue-gateway | `CapacityVersionState`     | Rebuildable (derived)                  | Cached capacity version numbers; re-derived from Postgres on first read. Nothing to restore.                                                                                                                                                                                                                                                                                                                       |
| sms-summary-gateway | `DailyBookingSummaryState` | **Authoritative** (idempotency ledger) | Records that a manager daily summary for `restaurant:localDate:recipient` was sent (`already_sent`, provider message id, sent-at) with a 35-day retention. Losing it can cause a **duplicate outbound message**. Do not replay the queue after a namespace loss until `queue-reconcile.ts` has compared the DLQ/backlog against the Postgres notification ledger and the Twilio message log, and never in a drill. |
| operational-control | (see its wrangler.jsonc)   | Rebuildable (derived)                  | Control-plane locks and heartbeats; rebuilt from GitHub state by the controller on its next tick.                                                                                                                                                                                                                                                                                                                  |

Rules:

1. Authoritative Durable Object state is never "restored" from a backup; it is **reconciled**. The reconciliation report is the input to any replay decision (`queue-reconcile.ts --confirm-replay` refuses without one).
2. Renaming a class or Worker creates a fresh namespace. Treat that as a loss event for authoritative classes and run the reconciliation before re-enabling the cron trigger.
3. Staging Workers run with `DELIVERY_MODE=sink` (SMS) / `RESEND_USE_MOCK=true` (email); drills use the same switches so no real recipient can be reached while state is being rebuilt.
