# How to contribute

Read `AGENTS.md` and `docs/sdlc/README.md` first. Classify risk with `docs/sdlc/risk-tier-workflow.md`, open a task folder for medium/high-risk work with `docs/sdlc/task-harness.md`, and verify using `docs/sdlc/verification.md`.

## Execution order

1. Name assumptions and non-goals.
2. Classify risk honestly.
3. Create task artifacts when required.
4. Declare route/API identity or say `Not applicable`.
5. Keep edits scoped to the success criteria.
6. Run matching validators and record exactly what happened.

Related: [Development workflow](development-workflow.md), [Testing](testing.md).
