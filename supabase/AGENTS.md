# AGENTS.md — Supabase Assets (`supabase/`)

> Inherits root `/AGENTS.md`. Applies to all Supabase configuration, migrations, generated artifacts, and CLI helpers within `supabase/**`.

## Overview

- Primary home for Supabase CLI state, secrets placeholders, and generated metadata (e.g., `.temp/` from CLI scaffolding).
- Source of truth for **remote-only** migrations, storage policies, auth configs, and SQL helpers referenced by the Next.js app.
- Changes here require tight coordination with release owners due to direct data impact.

## Build & Test Commands

- `pnpm supabase:status` (if scripted) or `supabase status --project-ref <ref>` — confirm remote env health before edits.
- `supabase migration list --db-url <REMOTE_URL>` — inventory existing migrations.
- `supabase migration new <name> --db-url <REMOTE_URL>` — create timestamped migrations; store output under `supabase/migrations/` (do **not** edit `.temp` contents directly).
- `supabase db diff --linked` — capture drift; save diff output to `tasks/<slug>/artifacts/db-diff.txt`.

## Guidelines

1. **Remote-Only Enforcement**
   - Never run `supabase start` or local Postgres; all commands must target staged/prod remote refs via env secrets.
   - Document target environment, backups, and approval chain in the task `plan.md` before applying changes.
2. **Migration Workflow**
   - Follow expansion → backfill → contraction for schema changes.
   - Store each SQL migration under `supabase/migrations/<timestamp>_<slug>.sql`; keep idempotent where possible.
   - Capture dry-run output (`supabase db diff --schema public --linked`) and place logs in task artifacts.
3. **Secrets & Config**
   - Do not commit real keys; only use `.env.example`-style placeholders.
   - `.temp/` files generated by Supabase CLI should remain untouched except during upgrades; remove sensitive info before committing.
4. **Coordination & Rollback**
   - Obtain sign-off from @db-owners + release manager prior to production applies.
   - Define rollback SQL or PITR steps in `plan.md` and confirm backups before merging.
5. **Testing & Observability**
   - After applying migrations to staging, run relevant integration tests (`pnpm test --filter server`, `pnpm test --filter guest`) and verify Supabase logs for errors.
   - Update monitoring/metrics references if schema changes affect dashboards.

## Required Artifacts

- Dry-run diff attached to `tasks/<slug>/artifacts/db-diff.txt`.
- Evidence of Supabase MCP session or CLI commands (screenshots/logs) stored alongside verification notes.
- Rollback plan summarized in `verification.md` before requesting review.
